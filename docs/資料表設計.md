# ToDo 資料表設計（v1，已確認）

架構：畫面前端 → API → 後端資料庫（純三層，不做本機快取）。
原則：每個任務一筆、每個值一個欄位，不把整包 JSON 存進單一欄位。

---

## 1. `tasks`：母任務

| 欄位 | 型別 | 可空白 | 預設值 | 說明 |
|---|---|---|---|---|
| `id` | UUID | 否 | 自動產生 | 主鍵 |
| `user_id` | UUID | 否 | | 屬於哪個使用者 |
| `title` | 文字 | 否 | | 標題 |
| `due_date` | 日期 | 是 | | 到期日；空白 = 無期限 |
| `note` | 文字 | 否 | `''` | 備註 |
| `is_done` | 是/否 | 否 | false | 是否已完成 |
| `done_at` | 日期時間 | 是 | | 完成時間 |
| `is_trashed` | 是/否 | 否 | false | 是否在垃圾桶 |
| `trashed_at` | 日期時間 | 是 | | 丟進垃圾桶的時間 |
| `created_at` | 日期時間 | 否 | 現在 | 建立時間（同組內排序也會用到） |
| `updated_at` | 日期時間 | 否 | 現在 | 最後修改時間 |

## 2. `subtasks`：子任務

| 欄位 | 型別 | 可空白 | 預設值 | 說明 |
|---|---|---|---|---|
| `id` | UUID | 否 | 自動產生 | 主鍵 |
| `task_id` | UUID | 否 | | 對應 `tasks.id`；母任務永久刪除時一併刪除 |
| `title` | 文字 | 否 | | 標題 |
| `due_date` | 日期 | 是 | | 到期日 |
| `note` | 文字 | 否 | `''` | 備註 |
| `is_done` | 是/否 | 否 | false | 是否已完成 |
| `done_at` | 日期時間 | 是 | | 完成時間 |
| `sort_order` | 整數 | 否 | 0 | 在母任務底下的排列順序 |
| `created_at` | 日期時間 | 否 | 現在 | 建立時間 |
| `updated_at` | 日期時間 | 否 | 現在 | 最後修改時間 |

## 3. `tiers`：緊急程度層級

| 欄位 | 型別 | 可空白 | 預設值 | 說明 |
|---|---|---|---|---|
| `id` | UUID | 否 | 自動產生 | 主鍵 |
| `user_id` | UUID | 否 | | 屬於哪個使用者 |
| `name` | 文字 | 否 | | 名稱，例如「三天內」 |
| `max_days` | 整數 | 是 | | 剩餘天數上限；負數 = 逾期；空白 = 其餘全部（含無期限），每個使用者只有一筆 |
| `color` | 文字 | 否 | | 色碼，例如 `#EE9A2A` |
| `hide_done` | 是/否 | 否 | false | 完成後是否移到已完成區 |
| `created_at` | 日期時間 | 否 | 現在 | 建立時間 |
| `updated_at` | 日期時間 | 否 | 現在 | 最後修改時間 |

排序依 `max_days` 由小到大（空白排最後）。

## 4. `user_settings`：個人設定（每個使用者一筆）

| 欄位 | 型別 | 可空白 | 預設值 | 說明 |
|---|---|---|---|---|
| `user_id` | UUID | 否 | | 主鍵 |
| `group_by` | 文字 | 否 | `earliest` | `earliest`（最急的日期）或 `self`（只看母任務自己） |
| `ui_theme` | 文字 | 否 | `tech-light` | `classic`、`tech-light`、`tech-dark` |
| `updated_at` | 日期時間 | 否 | 現在 | 最後修改時間 |

---

## 規則備忘

- 放進垃圾桶：`is_trashed = true`，資料仍保留。
- 永久刪除：真的刪除資料列，子任務跟著刪除。
- 每個使用者第一次登入時，建立預設的 5 個層級和一筆個人設定。
